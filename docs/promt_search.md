# Промпт: обновление каталога и поиск новых центров tatarverse

Ты работаешь как **OSINT-исследователь + инженер данных** в репозитории
tatarverse. У тебя две работы, и это разные работы:

- **Режим А — обновление.** Идёшь от существующих карточек: чинишь мёртвые
  ссылки, дописываешь контакты, оживляешь заглушки.
- **Режим Б — поиск.** Идёшь от пробелов каталога наружу: находишь
  организации, которых в каталоге нет.

Если задача не уточняет режим, **начинай с А**. Причина в разделе 3: две
трети каталога сейчас — выписки из справочника без единой рабочей ссылки, и
довести их до ума полезнее посетителю, чем добавить сотню новых таких же.

Документ объединяет исследовательскую стратегию с моделью каналов из
[Agent-Reach](https://github.com/Panniantong/Agent-Reach): для каждой площадки
известен основной путь и запасной, а перед работой выполняется диагностика,
показывающая, что реально доступно.

---

## 0. Главное правило

Не выдумывай данные. Не добавляй карточку ради счётчика. Не переписывай
проверенные данные без причины.

**Не утверждай, что использовал источник, к которому не было доступа.** Это не
абстракция: в этом окружении `*.tatarstan.ru` отдаёт `ECONNREFUSED`, а каталог
`tgstat` рисуется на клиенте и через `curl` выглядит пустым. Агент без
преflight-проверки честно напишет «сверено с реестром представительства» — и
это будет неправдой.

Поэтому работа начинается не с поиска, а с раздела 1.

## 1. Preflight: доктор каналов

**Выполняется до первого запроса.** Прогони пробу по каждому каналу и составь
таблицу доступности. Дальше опирайся только на каналы со статусом ✅.

| Канал | Основной путь | Запасной | Проба |
| --- | --- | --- | --- |
| Веб-страница | `WebFetch` | `curl -sL` | `curl -sL -o /dev/null -w "%{http_code}" <url>` |
| Веб-поиск | `WebSearch` | — | запрос с заведомо известным ответом |
| DNS | `dig @1.1.1.1 +short` | `dig @8.8.8.8` | `dig @1.1.1.1 +short tatarverse.cc` |
| Telegram | `curl` + `og:title` | `t.me/s/<handle>` | см. ниже |
| Instagram | `curl` код ответа | `WebSearch` по профилю | `curl -sL -o /dev/null -w "%{http_code}" https://www.instagram.com/<h>/` |
| VK / OK | `curl` код ответа | `WebSearch` | то же |
| Facebook | `curl` код ответа | `WebSearch` | то же |
| GitHub | `gh` CLI | `WebFetch` | `gh api /rate_limit` |
| YouTube | `WebFetch` | `WebSearch` | загрузка страницы канала |
| Реестры НКО | `WebFetch` | `WebSearch` | зависит от страны |

### Проба Telegram

Единственный надёжный способ отличить живой канал от несуществующего хэндла:

```bash
curl -sL --max-time 12 "https://t.me/<handle>" \
  | grep -o '<meta property="og:title" content="[^"]*"'
```

Несуществующий хэндл вернёт `Telegram: Contact @handle`. Живой канал вернёт
своё название. В `og:description` часто перечислены остальные соцсети
организации — готовый узел для обхода графа.

`https://t.me/s/<handle>` отдаёт публичный архив постов: годится для поиска
упоминаний других организаций.

### Вывод доктора

```
✅ Доступно:        WebSearch, WebFetch, curl, dig, Telegram-проба
⚠️  С оговорками:   Instagram (только код ответа, содержимое закрыто)
⬜ Недоступно:      prtuz.tatarstan.ru (ECONNREFUSED), tgstat (JS-рендер)

Итого: 5/8 каналов
```

Таблица целиком переносится в финальный отчёт. Канал ⬜ идёт в раздел
«недоступные источники», а не в список использованных. Отказал основной путь
посреди работы — переключайся на запасной и отмечай это.

## 2. Контракт данных: что репозиторий примет

Схема — источник истины. Она `.strict()`: **любое лишнее поле останавливает
сборку**, а не выдаёт предупреждение.

### Frontmatter: ровно семь полей

```yaml
---
title: Название организации          # обязательно
type: Зарубежный                     # Регион РФ | Зарубежный | Онлайн
category: Татарский                  # Татарский | Татаро-Башкирский |
                                     # Башкирский | Крымотатарский
source: https://example.org/         # один URL, главный источник
summary: Одно предложение о центре   # необязательно
pubDate: "2026-08-27"                # строка в кавычках, см. предупреждение
location:
  country: Узбекистан
  city: Ташкент
  region: Самаркандская область      # необязательно
  district: ...                      # необязательно
---
```

**`category` и `type` — закрытые перечисления.** Четыре категории, три типа.
Проект не ложится ни в одну — он вне каталога, а не повод расширять схему.

**`location.flag` не пиши никогда.** Флаг выводится из страны на рендере через
`countryFlagsByRu`.

**`pubDate` только строкой в кавычках.** Без кавычек YAML разберёт значение
как дату, схема ждёт строку, сборка упадёт.

> **`pubDate` не проставляй задним числом существующим карточкам.**
> Это дата появления в каталоге, и по ней идёт сортировка `byRecency`.
> Сейчас поле есть у 2 карточек из 421. Проставишь его старой карточке — она
> прыгнет на первое место каталога, в RSS, в подвал «Добавленные» и в бейдж
> главной, притворившись новинкой. При обновлении карточки поле не трогай.

### География: два жёстких реестра

- **Страна обязана быть в `src/data/geo/macroRegions.ts`** — сейчас там 59
  стран. Страна вне реестра роняет сборку с текстом «не отнесена ни к одному
  макрорегиону». Нашёл организацию в новой стране — сперва добавь страну с её
  макрорегионом, потом карточку.
- **Регион России обязан быть в `src/data/geo/ruRegions.ts`** — 89 субъектов с
  алиасами написаний. Нераспознанный регион тоже роняет сборку и подсказывает
  похожий вариант.

### Тело карточки: порядок разделов

```markdown
## Контакты

- Руководитель: Фамилия Имя Отчество
- Email: [info@example.org](mailto:info@example.org)
- Телефон: [+998712533991](tel:+998712533991)
- Адрес: город, улица, дом

## Ссылки

- [Сайт](https://example.org/)
- [Telegram](https://t.me/handle)
- [Instagram](https://instagram.com/handle)

## Особенности

- Год основания
- Отличительные факты списком

## О центре

Нейтральное описание фактами.

## Источники

- [Название источника](https://example.org/page)
```

**Быстрые кнопки собираются только из раздела `## Ссылки`** и только для семи
типов: сайт, Telegram, Instagram, VK, YouTube, Facebook, OK. Ссылка вне этого
раздела на карточке не появится.

**Одна ссылка на платформу.** `getCenterLinks` берёт первое вхождение каждого
типа, остальные игнорирует. Два телеграм-канала — на карточке будет один,
второму место в `## Источники`.

### Контакты: только публичные

Сайт, соцсети, рабочая почта, телефон организации. **Личные мобильные,
домашние адреса и приватные контакты людей — нельзя**, даже если они в
открытой выдаче. Имя руководителя можно, если опубликовано официально.

Типичная ловушка: в справочнике телефон организации и мобильный руководителя
кружка стоят рядом. Бери стационарный номер организации.

### Файлы и идентификаторы

- Русская карточка: `src/data/centers_formatted/tbk-<N>.mdx`, `<N>` —
  следующий свободный номер.
- Английский перевод: `src/data/centers_i18n/en/tbk-<N>.mdx`, тот же номер.
- **Номера стабильны и не переименовываются** — на них завязаны маршруты и
  внешние ссылки.

Без английского двойника центр не появится на `/en/` — `hasLocalizedRoute` его
исключит. Пиши в отчёте, сколько карточек осталось без перевода.

## 3. Режим А: обновление каталога

### Зачем это первично

Состояние каталога на 27 августа 2026, посчитано по файлам:

| Признак | Карточек | Доля |
| --- | ---: | ---: |
| Всего | 421 | 100% |
| Без раздела `## Ссылки` | 288 | 68% |
| С `source` = голая главная `tatar-congress.org` | 314 | 75% |
| Без `summary` | 393 | 93% |
| Без города | 191 | 45% |
| Тело короче 600 символов | 120 | 28% |
| Без раздела `## Контакты` | 84 | 19% |

Две трети каталога — выписка из справочника Всемирного конгресса татар:
название, город, фамилия руководителя и ссылка на главную страницу ВКТ вместо
источника. У такой карточки на сайте нет ни одной кликабельной кнопки.

Посетителю, который ищет своих рядом, нужна рабочая ссылка. Поэтому доведение
существующей карточки до контактов и соцсетей ценнее, чем ещё одна заглушка.

### Как выбрать, что обновлять

Собери список кандидатов одним проходом по файлам:

```bash
# карточки без раздела «Ссылки» — главная цель
grep -L '## Ссылки' src/data/centers_formatted/*.mdx | head -40

# карточки-заглушки: короткое тело
# wc -m, а не -c: кириллица в UTF-8 занимает два байта, и счёт байтов
# занизит выборку втрое
for f in src/data/centers_formatted/*.mdx; do
  n=$(sed -n '/^---$/,/^---$/!p' "$f" | wc -m)
  [ "$n" -lt 600 ] && echo "$n $f"
done | sort -n | head -40

# карточки без города
grep -L 'city:' src/data/centers_formatted/*.mdx | head -40
```

Приоритет: сперва страны и города, где организация точно существует и активна,
потом остальное. Группируй по стране — за один заход дешевле закрыть все
карточки одной страны, чем прыгать по миру.

### Проверка ссылок: код ответа ещё не приговор

Прогоняя существующие ссылки, **не считай мёртвым всё, что не отдало 200**.
Проверка на выборке из 30 ссылок каталога дала:

| Результат | Сколько | Что это значит |
| --- | ---: | --- |
| `200` | 24 | живо |
| `000` + нет DNS | 3 | **домен не существует**, ссылку убрать |
| `000` + DNS есть | 1 | сервер лежит или закрыт для этой сети — неясно |
| `403` | 1 | скорее всего блокирует `curl`, в браузере жив |

Различай два случая обязательно:

```bash
dig @1.1.1.1 +short <domain>     # пусто -> домена нет, ссылка мертва
curl -sL -o /dev/null -w "%{http_code}\n" --max-time 20 "<url>"
```

Пустой `dig` — приговор. `000` при живом DNS и `403` — повод перепроверить
другим путём (`WebFetch`, поиск по названию), а не удалять вслепую.

Нашёл мёртвую ссылку — **сперва ищи, куда организация переехала**. Часто
меняется только хэндл или домен, а сообщество живо.

### Секция `## Прочее`: не чистить вслепую

Она есть у 274 карточек, и содержимое разное:

| Что внутри | Карточек | Что делать |
| --- | ---: | --- |
| ОГРН / ИНН | 164 | **не трогать**, это реестровые данные |
| Дословный дубль остального тела | 43 | удалить |
| Прочее | 67 | смотреть глазами |

Дубли выглядят как обрезанная строка справочника: «Татаро-башкирский
культурный центр, г. Зарафшан. Руководитель – Амирова Фируза». Всё, что там
есть, уже стоит в `## Контакты` и `## О центре`.

Массовое удаление раздела уничтожит 164 ОГРН. Так делать нельзя.

### Что именно дописывать

По убыванию ценности:

1. **Раздел `## Ссылки`** — сайт и соцсети. Это единственное, что превращает
   заглушку в полезную карточку.
2. **Контакты организации** — рабочая почта, телефон, адрес.
3. **`source`** — заменить голую главную ВКТ на конкретную страницу, где
   организация реально описана.
4. **Город и регион** — если подтверждаются источником.
5. **`summary`** — одно предложение, из которого понятно, что это и где.
6. **`## О центре`** — фактами, без маркетинга.

### Правила правки существующего

- **Не переписывай проверенные данные без причины.** Нашёл ошибку — сперва
  подтверди её вторым источником, потом исправляй, потом отдельно скажи об
  этом в отчёте.
- **Не меняй `title` без необходимости** — он попадает в поисковый индекс и во
  внешние ссылки. Уточнение названия допустимо, если старое было явно
  обрезано или искажено.
- **Не трогай номер файла** и `pubDate` (см. предупреждение в разделе 2).
- Организация закрылась — не удаляй карточку молча. Отрази это в
  `## О центре` фактом с источником и вынеси в отчёт отдельным пунктом.

## 4. Режим Б: поиск новых организаций

### Сначала карта пробелов

Цель — **не набрать N карточек, а закрыть реальные пробелы**. Перед поиском
составь картину:

1. Какие страны представлены и сколькими центрами.
2. Какие страны отсутствуют полностью.
3. Где есть центры, но пропущены очевидные города.
4. Какие категории представлены плохо.

**Прочитай `docs/CENTERS-GAPS-CHECKLIST.md` до начала.** Там зафиксировано,
что уже искали и не нашли. Отметка ❌ «не подтверждено» означает: организации
нет в открытых источниках, повторять тот же запрос бессмысленно — нужен другой
класс источника.

### Четыре трека

Если среда позволяет параллельные субагенты — запусти их. Если нет — веди
последовательно и скажи об этом.

**Трек 1. Россия и СНГ.** Русский язык. Татарстан, Башкортостан, регионы с
крупной диаспорой (Москва, Петербург, Поволжье, Урал, Сибирь, Тюмень, ХМАО,
ЯНАО, Астрахань), затем Казахстан, Узбекистан, Кыргызстан, Беларусь.
Ищи центры, автономии, землячества, молодёжные и студенческие организации,
языковые и образовательные проекты, медиа.

**Трек 2. Дальнее зарубежье.** Английский как старт, дальше язык страны. США,
Канада, Великобритания, Германия, Финляндия, Швеция, Польша, Прибалтика,
Турция, Австралия, Ближний Восток, Восточная Азия. Не ограничивайся словом
`Tatar`: пробуй `Volga Tatar`, `Kazan Tatar`, `Crimean Tatar`,
`Tatar diaspora`, `Tatar heritage`, `Tatar cultural society`.

**Трек 3. Татарский и тюркские языки.** Татарская кириллица и латиница,
башкирский, казахский, турецкий, узбекский, кыргызский, азербайджанский.
Примеры: `татар оешмасы`, `татар яшьләре`, `татар җәмгыяте`, `татар мәдәни
үзәге`, `татар берлеге`. Задача — найти то, что плохо индексируется по русским
и английским запросам.

**Трек 4. Обход графа.** Не ещё один обычный поиск. Для каждой найденной
организации исследуй партнёров, учредителей, участников, спонсоров,
упоминания, обратные ссылки, соседей по каталогу организаций, организаторов и
участников мероприятий, ссылки в описании телеграм-канала и в link-in-bio.

Модель: `организация A → связанные сущности → организации B, C, D → их связи`.

**Этот трек здесь самый результативный.** Крымскотатарский центр «Авдет» в
Ташкенте нашёлся именно так — через соседей по каталогу организаций, а не
прямым запросом. До этого крымскотатарских центров в Узбекистане в каталоге не
было ни одного.

### Мероприятия как источник

Сабантуи, фестивали, форумы, съезды, конференции. У каждого есть организатор,
партнёры, спонсоры, участники, спикеры — каждый список это новые узлы графа.

### Что считается подходящим

Не только официальные НКО: сообщества, культурные и языковые проекты, медиа и
подкасты, телеграм-проекты, образовательные инициативы, землячества,
молодёжные объединения, фонды, фестивали, архивы, цифровые проекты.

Два ограничения:

- **Тематическая связь должна быть реальной.** Слова `Tatar` где-то на
  странице недостаточно.
- **Проект обязан лечь в схему.** Одна из четырёх категорий, один из трёх
  типов. Не ложится — в отклонённые с причиной «вне схемы каталога».

Личный аккаунт человека — не организация. Но профиль активиста отлично
работает как узел графа.

## 5. Языки

Приоритет — **релевантность языка стране, а не количество языков в отчёте**.

- **Глубоко:** татарский, русский, английский, турецкий, казахский,
  башкирский.
- **По необходимости:** язык страны, где нашлась организация или есть
  историческая диаспора.
- **Обязательного минимума языков нет.** Поиск на языке страны, где татарских
  организаций заведомо нет, — фиктивный мультиязычный поиск, запрещённый
  разделом 0.

В отчёте раздели языки на глубокие, вспомогательные, пробованные без
результата и продуктивные.

## 6. Транслитерации и дедупликация

Одна организация живёт под несколькими именами. Ищи и сверяй одновременно:
оригинальное название, татарскую кириллицу, латиницу, английскую и русскую
транслитерации, официальный перевод.

`Бөтендөнья татар яшьләре форумы` = `Bötendönya Tatar Yäşläre Forumı` =
`World Forum of Tatar Youth` = `Всемирный форум татарской молодёжи` — это
**одна** запись.

Перед добавлением сверь с датасетом по названию (нечётко), домену, хэндлам в
Telegram, Instagram, VK, Facebook, городу, стране, руководителю.

Отдельно решай: самостоятельная организация или подразделение, филиал,
мероприятие либо вторая соцсеть той же организации. Локальное отделение —
отдельная карточка, только если работает как самостоятельное сообщество.

## 7. Проверка находки

### Источники по приоритету

1. официальный сайт;
2. официальная соцсеть организации;
3. государственный реестр;
4. сайт родительской организации;
5. авторитетное СМИ;
6. университет или организатор мероприятия;
7. каталог организаций;
8. сторонние публикации.

Википедия годится для обнаружения, но не как единственный источник.

Стремись к двум независимым подтверждениям. Одного очевидного официального
первоисточника достаточно.

### Каждый URL проверяй пробой

Не переноси ссылку из выдачи не открыв её. Проверь: страница существует,
относится к нужной организации, нет редиректа на чужой проект, домен не
припаркован, аккаунт не удалён. Команды и трактовка кодов — в разделе 3.

### Активность

Не считай организацию действующей только потому, что домен отвечает. Смотри
дату последней публикации, анонсы, недавние упоминания. Организация
исторически значима, но замолчала — это допустимо, скажи об этом честно в
описании.

### Уверенность

`high` — официальный источник плюс подтверждение. `medium` — официальная
соцсеть или несколько надёжных вторичных источников. `low` — мало информации,
старые упоминания, сомнительная идентификация.

`low` не добавляй автоматически: сперва попробуй подтвердить.

## 8. Работа партиями

Партия — **10-20 карточек** в любом режиме.

Цикл: discovery или аудит → доказательства → пробы ссылок → релевантность →
дедупликация → запись файлов → `bunx astro check` → `bun run build` →
следующая партия.

После каждой партии репозиторий обязан собираться. «Двести карточек, но сайт
не собирается» недопустимо.

## 9. Журнал исследования

| Организация | Страна | Язык | Трек | Источники | Уверенность | Дубль | Действие |
| --- | --- | --- | --- | --- | --- | --- | --- |

В колонке «Действие»: добавлена, обновлена, отклонена, ссылка починена, ссылка
удалена как мёртвая.

Отдельно — отклонённые кандидаты с причиной: дубль, нерелевантно, нет
доказательств, мёртвый проект, частное лицо, недостаточно информации, вне
схемы каталога.

**Итог дописывай в `docs/CENTERS-GAPS-CHECKLIST.md`.** Это постоянная память
проекта между сессиями. Отрицательный результат фиксируй тоже: «искали X через
Y, не нашли» экономит следующему проходу целый день.

## 10. Проверки

В проекте **нет** ни форматтера, ни линтера, ни тестов. Не пытайся их
запускать. Реальных проверок две:

```bash
bunx astro check   # типы и схемы коллекций
bun run build      # полная сборка
```

Версию в `package.json` и `src/data/release.json` руками не трогай — этим
занимается `bun run release:bump`, он же дёргается pre-push хуком.

Завершать работу с неработающей сборкой нельзя.

## 11. Финальный отчёт

**Режим.** А, Б или оба, и почему.

**Каналы.** Таблица из раздела 1: доступно, с оговорками, недоступно и почему.

**Обновление.** Сколько карточек обновлено. Сколько ссылок проверено, сколько
оказалось мёртвыми, сколько удалось заменить актуальными. Сколько заглушек
доведено до рабочего состояния. Отдельно — найденные и исправленные ошибки в
существующих данных.

**Поиск.** Найдено кандидатов, добавлено, отклонено с основными причинами,
дублей обнаружено.

**География.** Новые страны, регионы, города. Отдельно — страны, добавленные в
`macroRegions.ts`.

**Языки.** Таблица: язык, кандидаты, уникальные находки, добавлено. С
разделением на глубокие, вспомогательные, безрезультатные, продуктивные.

**Переводы.** Сколько карточек осталось без английской версии.

**Проверки.** Результат `astro check` и `build`.

**Оставшиеся пробелы.** Плохо исследованные страны и языки, недоступные
источники, направления следующего прохода. Дописывается в
`CENTERS-GAPS-CHECKLIST.md`.

## 12. Работа сделана, когда

- preflight выполнен, таблица каналов честная;
- в режиме А: ссылки проверены пробами, мёртвые различены от временно
  недоступных, заглушки доведены до рабочих карточек, ОГРН не пострадали;
- в режиме Б: шёл от пробелов, использовал обход графа, а не только прямые
  запросы;
- дедупликация проведена, включая транслитерации;
- ни одного поля вне схемы, ни одного флага в MDX, ни одного личного
  контакта, ни одного `pubDate` задним числом;
- `astro check` и `build` проходят;
- журнал дописан в `CENTERS-GAPS-CHECKLIST.md`;
- отчёт показывает реальный масштаб, включая то, что найти не удалось.

## 13. Главное

Не останавливайся на первой сотне результатов выдачи. Иди по цепочке:

**страна → язык → запрос → организация → сайт → соцсети → партнёры →
мероприятия → участники → связанные организации → новые проекты**

и повторяй цикл.

Но помни, ради чего. Цель не в том, чтобы каталог стал больше, а в том, чтобы
человек, ищущий своих, нашёл рядом с собой живую организацию с рабочей
ссылкой. Карточка с одной фамилией из справочника этой задачи не решает —
поэтому режим А идёт первым.
