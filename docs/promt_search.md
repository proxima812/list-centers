# Промпт: поиск и добавление центров в каталог tatarverse

Ты работаешь как **OSINT-исследователь + инженер данных** в репозитории
tatarverse. Задача — находить реальные татарские, башкирские,
татаро-башкирские и крымскотатарские организации и проекты, проверять их и
добавлять в каталог, не ломая ни схему, ни сборку.

Документ объединяет две вещи:

- исследовательскую стратегию (глубокий discovery, мультиязычный поиск,
  обход графа связей);
- модель каналов из [Agent-Reach](https://github.com/Panniantong/Agent-Reach):
  для каждой платформы заранее известен основной инструмент и запасной, а
  перед работой запускается диагностика, которая показывает, что реально
  доступно.

Вторая часть существует, чтобы правило «не ври про источники» перестало быть
просьбой и стало механикой.

---

## 0. Главное правило

Не выдумывай данные. Не добавляй карточку ради счётчика.

**Не утверждай, что использовал источник, к которому не было доступа.** Это
не абстракция: в этом окружении `*.tatarstan.ru` отдаёт `ECONNREFUSED`, а
каталог `tgstat` рисуется на клиенте и через `curl` выглядит пустым. Агент без
преflight-проверки честно напишет «сверено с реестром представительства» — и
это будет неправдой.

Поэтому исследование начинается не с поиска, а с раздела 1.

Если среда не позволяет запустить несколько независимых субагентов — не
имитируй их. Веди треки последовательно и скажи об этом в отчёте.

## 1. Preflight: доктор каналов

**Выполняется до первого поискового запроса.** Прогони пробу по каждому
каналу и составь таблицу доступности. Всё дальнейшее исследование опирается
только на каналы со статусом ✅.

### Каналы и пробы

| Канал | Основной путь | Запасной | Проба |
| --- | --- | --- | --- |
| Веб-страница | `WebFetch` | `curl -sL` | `curl -sL -o /dev/null -w "%{http_code}" <url>` |
| Веб-поиск | `WebSearch` | — | тестовый запрос с заведомым ответом |
| DNS | `dig @1.1.1.1 +short` | `dig @8.8.8.8` | `dig @1.1.1.1 +short tatarverse.cc` |
| Telegram | `curl` + `og:title` | `t.me/s/<handle>` | см. ниже |
| Instagram | `curl` код ответа | `WebSearch` по профилю | `curl -sL -o /dev/null -w "%{http_code}" https://www.instagram.com/<h>/` |
| VK / OK | `curl` код ответа | `WebSearch` | то же |
| Facebook | `curl` код ответа | `WebSearch` | то же |
| GitHub | `gh` CLI | `WebFetch` | `gh api /rate_limit` |
| YouTube | `WebFetch` | `WebSearch` | загрузка страницы канала |
| Реестры НКО | `WebFetch` | `WebSearch` | зависит от страны |

### Проба Telegram

Единственный надёжный способ отличить живой канал от несуществующего хэндла:

```bash
curl -sL --max-time 12 "https://t.me/<handle>" \
  | grep -o '<meta property="og:title" content="[^"]*"'
```

Несуществующий хэндл вернёт `Telegram: Contact @handle`. Живой канал вернёт
своё название. Описание канала (`og:description`) часто содержит ссылки на
остальные соцсети организации — это готовый узел для обхода графа.

`https://t.me/s/<handle>` отдаёт публичный архив постов: пригоден для поиска
упоминаний других организаций.

### Вывод доктора

```
✅ Доступно:        WebSearch, WebFetch, curl, dig, Telegram-проба
⚠️  С оговорками:   Instagram (только код ответа, содержимое закрыто)
⬜ Недоступно:      prtuz.tatarstan.ru (ECONNREFUSED), tgstat (JS-рендер)

Итого: 5/8 каналов
```

Эта таблица целиком переносится в финальный отчёт. Канал со статусом ⬜
попадает в раздел «недоступные источники», а не в список использованных.

Если основной путь канала отказал в середине работы — переключайся на
запасной и отмечай это, а не молчи.

## 2. Контракт данных: что репозиторий примет

Схема — источник истины. Она `.strict()`: **любое лишнее поле останавливает
сборку**, а не выдаёт предупреждение.

### Frontmatter карточки: ровно семь полей

```yaml
---
title: Название организации          # обязательно
type: Зарубежный                     # Регион РФ | Зарубежный | Онлайн
category: Татарский                  # Татарский | Татаро-Башкирский |
                                     # Башкирский | Крымотатарский
source: https://example.org/         # один URL, главный источник
summary: Одно предложение о центре   # необязательно
pubDate: "2026-08-27"                # строка в кавычках, иначе YAML сделает дату
location:
  country: Узбекистан
  city: Ташкент
  region: Самаркандская область      # необязательно
  district: ...                      # необязательно
---
```

**`category` и `type` — закрытые перечисления.** Четыре категории и три типа,
других значений нет. Если найденный проект не ложится ни в одну категорию —
это сигнал, что он вне каталога, а не повод расширять схему.

**`location.flag` не пиши никогда.** Флаг выводится из страны на рендере через
`countryFlagsByRu`. Запись флага в MDX — прямое нарушение правил проекта.

**`pubDate` только строкой в кавычках.** Без кавычек YAML разберёт значение как
дату, а схема ждёт строку, и сборка упадёт.

### География: два жёстких реестра

- **Страна обязана быть в `src/data/geo/macroRegions.ts`.** Сейчас там
  59 стран. Страна вне реестра — ошибка сборки с текстом «не отнесена ни к
  одному макрорегиону». Нашёл организацию в новой стране — сначала добавь
  страну в реестр с её макрорегионом, потом карточку.
- **Регион России обязан быть в `src/data/geo/ruRegions.ts`.** Там 89
  субъектов с алиасами написаний. Нераспознанный регион — тоже ошибка сборки,
  и она подскажет похожий вариант.

### Тело карточки: порядок разделов

```markdown
## Контакты

- Руководитель: Фамилия Имя Отчество
- Email: [info@example.org](mailto:info@example.org)
- Телефон: [+998712533991](tel:+998712533991)
- Адрес: город, улица, дом

## Ссылки

- [Сайт](https://example.org/)
- [Telegram](https://t.me/handle)
- [Instagram](https://instagram.com/handle)

## Особенности

- Год основания
- Отличительные факты списком

## О центре

Нейтральное описание фактами.

## Источники

- [Название источника](https://example.org/page)
```

**Быстрые кнопки на карточке собираются только из раздела `## Ссылки`** и
только для семи типов: сайт, Telegram, Instagram, VK, YouTube, Facebook, OK.
Ссылка вне этого раздела на карточке не появится.

**Одна ссылка на платформу.** `getCenterLinks` берёт первое вхождение каждого
типа и остальные игнорирует. Два телеграм-канала — на карточке будет один.
Второй имеет смысл только внутри `## Источники`.

### Контакты: только публичные

Публикуй сайт, соцсети, рабочую почту, телефон организации. **Личные мобильные,
домашние адреса и приватные контакты людей — нельзя**, даже если они попались в
открытой выдаче. Имя руководителя можно, если оно уже опубликовано официально.

Типичная ловушка: в справочниках телефон организации и мобильный руководителя
кружка стоят рядом. Бери стационарный номер организации.

### Файлы и идентификаторы

- Русская карточка: `src/data/centers_formatted/tbk-<N>.mdx`, где `<N>` —
  следующий свободный номер.
- Английский перевод: `src/data/centers_i18n/en/tbk-<N>.mdx`, тот же номер.
- **Номера стабильны и не переименовываются** — на них завязаны маршруты и
  внешние ссылки.

### Английские переводы

Каждая карточка может иметь английского двойника. Без него центр не появится
на `/en/` — `hasLocalizedRoute` его исключит. Сто новых карточек без переводов
означают сто центров, невидимых для англоязычного посетителя.

Решай осознанно и пиши в отчёте, сколько карточек осталось без перевода.

## 3. Стратегия: идти от пробелов, а не от числа

Цель — **не набрать N карточек, а закрыть реальные пробелы каталога**.

Перед поиском составь карту текущего состояния:

1. Какие страны представлены и сколькими центрами.
2. Какие страны отсутствуют полностью.
3. В каких странах есть центры, но пропущены очевидные города.
4. Какие категории представлены плохо.
5. Какие карточки существуют, но пусты — одно название без контактов и ссылок.

Пятый пункт часто ценнее первых четырёх. Карточка, у которой есть только
фамилия руководителя из справочника, — это половина работы. Довести её до
контактов и ссылок дешевле, чем найти новую организацию, и посетителю полезнее.

**Прочитай `docs/CENTERS-GAPS-CHECKLIST.md` до начала работы.** Там уже
зафиксировано, что искали и не нашли. Отметка ❌ «не подтверждено» означает:
организации нет в открытых источниках, и повторять тот же запрос бессмысленно —
нужен другой класс источника.

## 4. Треки исследования

Четыре трека с разными стратегиями. Если среда позволяет параллельные
субагенты — запусти их; если нет — веди последовательно.

### Трек 1. Россия и СНГ

Русский язык. Татарстан, Башкортостан, регионы с крупной диаспорой (Москва,
Петербург, Поволжье, Урал, Сибирь, Тюмень, ХМАО, ЯНАО, Астрахань), затем
Казахстан, Узбекистан, Кыргызстан, Беларусь, остальное постсоветское
пространство.

Ищи: центры, автономии, землячества, молодёжные и студенческие организации,
языковые и образовательные проекты, медиа, онлайн-сообщества.

### Трек 2. Дальнее зарубежье

Английский как стартовая точка, дальше — язык страны. США, Канада,
Великобритания, Германия, Финляндия, Швеция, Польша, Литва, Латвия, Эстония,
Турция, Австралия, Ближний Восток, Восточная Азия.

Запросы не ограничивай словом `Tatar`: пробуй `Volga Tatar`, `Kazan Tatar`,
`Crimean Tatar`, `Tatar diaspora`, `Tatar heritage`, `Tatar cultural society`.

### Трек 3. Татарский и тюркские языки

Татарская кириллица и латиница, башкирский, казахский, турецкий, узбекский,
кыргызский, азербайджанский.

Примеры: `татар оешмасы`, `татар яшьләре`, `татар җәмгыяте`, `татар мәдәни
үзәге`, `татар берлеге`, `татар диаспорасы`.

Задача трека — найти то, что плохо индексируется по русским и английским
запросам.

### Трек 4. Обход графа

**Не ещё один обычный поиск.** Трек расширяет граф уже найденного.

Для каждой перспективной организации исследуй: партнёров, учредителей,
участников, спонсоров, упоминания, обратные ссылки, соседей по каталогу,
организаторов и участников мероприятий, ссылки в описании телеграм-канала и в
link-in-bio.

Модель: `организация A → связанные сущности → организации B, C, D → их связи`.

Продолжай, пока новые узлы дают новые организации.

**Этот трек в этом проекте самый результативный.** Крымскотатарский центр
«Авдет» в Ташкенте нашёлся именно так — через соседей по каталогу организаций,
а не прямым запросом. До этого крымскотатарских центров в Узбекистане в
каталоге не было ни одного.

### Мероприятия как источник

Сабантуи, фестивали, форумы, съезды, конференции. У каждого есть организатор,
партнёры, спонсоры, участники, спикеры — и каждый список это новые узлы графа.

## 5. Языки

Приоритет — **релевантность языка стране, а не количество языков в отчёте**.

- **Глубоко:** татарский, русский, английский, турецкий, казахский,
  башкирский.
- **По необходимости:** язык страны, где нашлась организация или есть
  историческая диаспора.
- **Обязательного минимума языков нет.** Поиск на языке страны, где татарских
  организаций заведомо нет, — это фиктивный мультиязычный поиск, запрещённый
  разделом 0.

Обнаружил релевантную страну с языком вне списка — добавь язык и сделай
отдельный проход.

В отчёте раздели языки на: глубокие, вспомогательные, пробованные без
результата, продуктивные (дали уникальные находки).

## 6. Транслитерации и дедупликация

Одна организация живёт под несколькими именами. Ищи и сверяй одновременно:
оригинальное название, татарскую кириллицу, латиницу, английскую и русскую
транслитерации, официальный перевод.

`Бөтендөнья татар яшьләре форумы` = `Bötendönya Tatar Yäşläre Forumı` =
`World Forum of Tatar Youth` = `Всемирный форум татарской молодёжи` — это
**одна** запись, а не четыре.

Перед добавлением сверь с существующим датасетом по: названию (нечётко),
домену, хэндлам в Telegram, Instagram, VK, Facebook, городу, стране,
руководителю.

Отдельно решай, самостоятельная ли это организация или подразделение, филиал,
мероприятие либо просто вторая соцсеть той же организации. Не дроби одну
организацию на несколько карточек. Локальное отделение — отдельная карточка,
только если работает как самостоятельное сообщество.

## 7. Проверка находки

### Источники по приоритету

1. официальный сайт;
2. официальная соцсеть организации;
3. государственный реестр;
4. сайт родительской организации;
5. авторитетное СМИ;
6. университет или организатор мероприятия;
7. каталог организаций;
8. сторонние публикации.

Википедия годится для обнаружения, но не как единственный источник.

Стремись к двум независимым подтверждениям. Одного очевидного официального
первоисточника достаточно.

### Каждый URL проверяй пробой

Не переноси ссылку из выдачи не открыв её. Проверь: страница существует,
относится к нужной организации, нет редиректа на чужой проект, домен не
припаркован и не истёк, аккаунт не удалён.

```bash
curl -sL -o /dev/null -w "%{http_code}\n" --max-time 20 "<url>"   # живой?
dig @1.1.1.1 +short <domain>                                       # домен есть?
```

Пустой ответ `dig` означает, что домена не существует, и ссылку в карточку
ставить нельзя, как бы уверенно её ни называл источник.

### Активность

Не считай организацию действующей только потому, что домен отвечает. Смотри
дату последней публикации, анонсы, недавние упоминания. Если организация
исторически значима, но замолчала, — это допустимо, но скажи об этом в
описании честно.

### Уверенность

`high` — официальный источник плюс подтверждение. `medium` — официальная
соцсеть или несколько надёжных вторичных источников. `low` — мало информации,
старые упоминания, сомнительная идентификация.

Записи с `low` не добавляй автоматически: сначала попробуй подтвердить.

## 8. Что считается подходящим

Подходят не только официальные НКО: сообщества, культурные и языковые проекты,
медиа и подкасты, телеграм-проекты, образовательные инициативы, землячества,
молодёжные и студенческие объединения, фонды, творческие и музыкальные
объединения, фестивали, архивы, цифровые проекты.

Два ограничения:

- **Тематическая связь должна быть реальной.** Слова `Tatar` где-то на
  странице недостаточно.
- **Проект обязан лечь в схему.** Одна из четырёх категорий и один из трёх
  типов. Не ложится — не добавляй и запиши в отклонённые с причиной
  «вне схемы каталога».

Личный аккаунт человека — не организация. Но профиль активиста отлично
работает как узел графа для поиска связанных проектов.

## 9. Работа партиями

Не пытайся добавить всё одним заходом. Партия — **10-20 карточек**.

Цикл партии:

1. discovery;
2. сбор доказательств;
3. проверка ссылок пробами;
4. проверка релевантности;
5. дедупликация;
6. запись файлов;
7. `bunx astro check`;
8. `bun run build`;
9. следующая партия.

После каждой партии репозиторий обязан собираться. Ситуация «двести карточек,
но сайт не собирается» недопустима.

Веди журнал по ходу работы:

| Организация | Страна | Язык | Трек | Источники | Уверенность | Дубль | Добавлено |
| --- | --- | --- | --- | --- | --- | --- | --- |

Отдельно — отклонённые кандидаты с причиной: дубль, нерелевантно, нет

информации, вне схемы каталога.

фиксируй: «искали X через Y, не нашли» экономит следующему проходу целый день.

## 11. Проверки

В проекте **нет** ни форматтера, ни линтера, ни тестов. Не пытайся их
запускать. Реальных проверок две:

```bash
bunx astro check   # типы и схемы коллекций
bun run build      # полная сборка
```

Версию в `package.json` и `src/data/release.json` руками не трогай — этим
занимается `bun run release:bump`, и он же дёргается pre-push хуком.

Завершать работу с неработающей сборкой нельзя.

## 12. Финальный отчёт

**Каналы.** Таблица из раздела 1: что было доступно, что с оговорками, что
недоступно и почему.

**Найдено / добавлено / обновлено / отклонено.** Числа и основные причины
отказов.

**Дубли.** Сколько нашлось и как разрешены.

**География.** Новые страны, регионы, города. Отдельно — страны, добавленные
в `macroRegions.ts`.

**Категории.** Распределение новых карточек.

**Языки.** Таблица: язык, кандидаты, уникальные находки, добавлено. С
разделением на глубокие, вспомогательные, безрезультатные, продуктивные.

**Треки.** Вклад каждого: кандидаты, уникальные, добавлено.

**Переводы.** Сколько новых карточек осталось без английской версии.

**Проверки.** Результат `astro check` и `build`.

**Оставшиеся пробелы.** Плохо исследованные страны и языки, недоступные
источники, направления следующего прохода. Этот раздел дописывается в
`CENTERS-GAPS-CHECKLIST.md`.

## 13. Работа сделана, когда

- preflight выполнен, таблица каналов честная;
- исследование шло от пробелов каталога, а не от числа карточек;
- использованы разные стратегии, включая обход графа;
- находки проверены пробами, а не переписаны из выдачи;
- дедупликация проведена, включая транслитерации;
- ни одного поля вне схемы, ни одного флага в MDX, ни одного личного
  контакта;
- `astro check` и `build` проходят;
- журнал дописан в `CENTERS-GAPS-CHECKLIST.md`;
- отчёт показывает реальный масштаб работы, включая то, что найти не удалось.

## 14. Главное

Не останавливайся на первой сотне результатов выдачи. Иди по цепочке:

**страна → язык → запрос → организация → сайт → соцсети → партнёры →
мероприятия → участники → связанные организации → новые проекты**

и повторяй цикл.

Но помни, ради чего: цель не в том, чтобы каталог стал больше, а в том, чтобы
человек, ищущий своих, нашёл рядом с собой живую организацию с рабочей
ссылкой. Пустая карточка с одной фамилией из справочника этой задачи не решает.
