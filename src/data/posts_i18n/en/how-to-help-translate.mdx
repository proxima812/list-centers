We are looking for people who know Tatar, Kazakh, Bashkir, or Crimean Tatar and are willing to help with translation. The question we get most is a simple one: where do I write?

## Write to us

Anywhere on this list - it makes no difference, we read all of them:

- Telegram: [@the_tatarverse](https://t.me/the_tatarverse), or the developer directly at [@mirikhan1](https://t.me/mirikhan1)
- Instagram: [@the_tatarverse](https://www.instagram.com/the_tatarverse/)
- VK: [@the_tatarverse](https://vk.ru/the_tatarverse)
- Threads: [@the_tatarverse](https://www.threads.com/@the_tatarverse)
- [Email](mailto:kamil.mirikhan@gmail.com?subject=Hello%21%20writing%20from%20tatarverse.cc)

The same contacts always sit in the site footer, under "Contact".

One line is enough: which language you know. What to translate we will work out together. You can also send finished text right away - just say where it came from: a post, a center card, or the interface strings. There is no form, no questionnaire, no sign-up.

You do not have to take on the whole site. One post, one card, or a dozen interface strings is already help, and changes that size reach the site fastest.

## If you prefer GitHub

The site is open and all of its text lives in the repository [github.com/proxima812/tatarverse](https://github.com/proxima812/tatarverse) as plain files. If that is where you feel at home, here is what sits where:

- posts - in `src/data/posts`
- interface strings - in `src/i18n/locales/ru.ts` and `en.ts`
- center cards - in `src/data/centers_formatted`, with English versions in `src/data/centers_i18n/en`

There is no folder yet for Tatar, Kazakh, Bashkir, or Crimean Tatar: setting up an empty structure before the first translation made no sense. So the simplest route is to open an [issue](https://github.com/proxima812/tatarverse/issues/new), paste the translation in, and say which language it is. We will file it into the right places ourselves.

If a pull request is no trouble for you, translate any Russian file in full and open one. Mention in the description that the structure for that language does not exist yet and you are proposing the first version - then we will set it up together with your change.

The whole process with a fork and a local run is written out in [CONTRIBUTING.en.md](https://github.com/proxima812/tatarverse/blob/main/CONTRIBUTING.en.md) (the Russian version is [CONTRIBUTING.ru.md](https://github.com/proxima812/tatarverse/blob/main/CONTRIBUTING.ru.md)). In short: `bun install`, `bun run dev`, a branch with the `i18n/` prefix, for example `i18n/kk-how-to-help-translate`. Commits follow Conventional Commits, along the lines of `feat(i18n): add Kazakh translation of the how-to-help-translate post`. One pull request means one language of one text: that way it can be merged straight away, without waiting for everything else to be translated.

Two questions people ask most often. You do not need an `.env` file for translation, and it is not in the repository anyway. And the `pre-push` hook that bumps the release version is not enabled in a fork by default; if it does get in the way, use `RELEASE_BUMP_SKIP=1 git push`.

One last thing: GitHub is a route for people who like it, not a requirement. A translation sent over Telegram or email arrives just the same.
