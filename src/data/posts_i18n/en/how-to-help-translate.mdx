In the [previous post](/en/posts/need-translators) we wrote that we are looking for people who know Tatar, Kazakh, Bashkir, or Crimean Tatar and are willing to help with translation. Here is the detail - how exactly to do it, by any of several routes.

**Through GitHub.** The site's repository is open: [github.com/proxima812/tatarverse](https://github.com/proxima812/tatarverse). The texts of the posts live in `src/data/posts`, the interface strings in `src/i18n/locales/ru.ts` and `en.ts`, the center cards in `src/data/centers_formatted` (Russian) and `src/data/centers_i18n/en` (English). There is no separate folder for Tatar, Kazakh, Bashkir, or Crimean Tatar yet, so the easiest way to start is an [issue](https://github.com/proxima812/tatarverse/issues/new): paste in your translation of a post, a center description, or an interface string, and say which language it is. If you are comfortable with pull requests, translate any Russian file in full and open a PR, explaining in the description that the structure for that language has not been set up and you are proposing the first version.

**For those who are at home with Git.** If you have worked with forks and pull requests before, the full process is written out in [CONTRIBUTING.en.md](https://github.com/proxima812/tatarverse/blob/main/CONTRIBUTING.en.md) (and in the Russian version, [CONTRIBUTING.ru.md](https://github.com/proxima812/tatarverse/blob/main/CONTRIBUTING.ru.md)): fork the repository, install the dependencies with `bun install`, bring the site up locally with `bun run dev`, and create a branch for the task with the `i18n/` prefix, for example `i18n/kk-need-translators`. Commits follow Conventional Commits, along the lines of `feat(i18n): add Kazakh translation of the need-translators post`. One pull request means one language of one text - that way it is easier to review and to merge in pieces, without waiting for everything to be translated at once.

Two things people usually ask about. You do not need `.env` for translation - it is only needed by the server-side submission forms, and it is not in the repository. And the `pre-push` hook that bumps the release version on push is not active in a fork by default; if it does get in the way, use `RELEASE_BUMP_SKIP=1 git push`.

**Through Telegram.** Write to the [Бәйсез](https://t.me/the_tatarverse) channel - you can reach the developer directly there, or by direct message at [t.me/isembez](https://t.me/isembez). Tell us which language you know and what you are ready to translate; everything else is worked out in the conversation, and no separate form is needed.

**Other ways.** An [email](mailto:kamil.mirikhan@gmail.com?subject=Hello%21%20writing%20from%20tatarverse.cc) works the same way as Telegram - you can attach a translation straight away, or simply say that you are willing to help. Instagram [@the_tatarverse](https://www.instagram.com/the_tatarverse/) is read too, but for a substantive conversation about translation email or Telegram is more convenient.

What to translate is something we decide together. You do not have to take on the whole site at once - one post, one center card, or a few interface strings will do.
