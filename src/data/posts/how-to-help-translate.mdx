Эти же контакты всегда лежат в подвале сайта, в разделе «Связь».

Достаточно одной строчки: какой язык знаете. Что переводить, придумаем вместе. Можно и сразу прислать готовый текст - просто скажите, откуда он: пост, карточка центра или надписи в интерфейсе. Никакой формы, анкеты и регистрации нет.

Браться за весь сайт не нужно. Один пост, одна карточка или десяток строк интерфейса - это уже помощь, и такие правки доходят до сайта быстрее всего.

## Если хотите через GitHub

Сайт открытый, весь текст лежит в репозитории [github.com/proxima812/tatarverse](https://github.com/proxima812/tatarverse) обычными файлами. Кому привычнее работать там - вот что где:

- посты - в `src/data/posts`
- надписи интерфейса - в `src/i18n/locales/ru.ts` и `en.ts`
- карточки центров - в `src/data/centers_formatted`, английские версии - в `src/data/centers_i18n/en`

Папки для татарского, казахского, башкирского и крымскотатарского пока нет: заводить пустую структуру раньше первого перевода смысла не было. Поэтому самый простой путь - открыть [issue](https://github.com/proxima812/tatarverse/issues/new), вставить туда перевод и написать, какой это язык. Дальше мы сами разложим его по файлам.

Если pull request для вас не проблема, переведите любой русский файл целиком и откройте PR. В описании упомяните, что структуры для этого языка еще нет и вы предлагаете первый вариант, - тогда мы заведем ее вместе с вашей правкой.

Весь процесс с форком и локальным запуском расписан в [CONTRIBUTING.ru.md](https://github.com/proxima812/tatarverse/blob/main/CONTRIBUTING.ru.md) (английская версия - [CONTRIBUTING.en.md](https://github.com/proxima812/tatarverse/blob/main/CONTRIBUTING.en.md)). Коротко: `bun install`, `bun run dev`, ветка с префиксом `i18n/`, например `i18n/kk-need-translators`. Коммиты в формате Conventional Commits, вроде `feat(i18n): добавлен казахский перевод поста need-translators`. Один pull request - один язык одного текста: так его можно смержить сразу, не дожидаясь, пока переведется все остальное.

Два вопроса, которые задают чаще всего. Файл `.env` для перевода не нужен, его в репозитории и нет. А хук `pre-push`, который поднимает версию релиза, в форке по умолчанию не включен; если он все же мешает - `RELEASE_BUMP_SKIP=1 git push`.

И на всякий случай: гитхаб - это способ для тех, кому он удобен, а не обязательное условие. Через телеграм или почту перевод дойдет ровно так же.
