# tatarverse Collab

В этом репозитории параллельно работают Claude Code и Codex. Скилл нужен,
когда задачу осмысленно разделить, а не когда её проще сделать целиком.

## Общая база

Оба агента читают одни и те же файлы: `AGENTS.md` (правила проекта, стек,
коллекции), `CLAUDE.md` (отличия для Claude), `DESIGN.md` и
`.impeccable/design.json` (дизайн-система). Скиллы лежат в `.agents/skills/`,
`.claude/skills/` симлинкает на них - правь оригинал в `.agents/`.
Исключение - `.claude/skills/impeccable/`: это отдельная сборка вендора под
Claude, обновляется только через `bunx skills add`.

Перед началом работы и перед пушем - `git pull --rebase`, чтобы не потерять
правки второго агента.

## Разделение ролей

- **UI/UX-направление**: модель взаимодействия, замысел лейаута, иерархия
  информации, ясность копирайта, ожидания по доступности, адаптив,
  визуальные критерии приёмки.
- **Реализация**: чтение текущего кода Astro, узкие правки, соблюдение
  конвенций проекта, лёгкая валидация, точный список изменённых файлов.
- При расхождении - выбирается наименьшая реализация, удовлетворяющая
  UI/UX-замыслу и правилам проекта.

## Workflow

1. Посмотри затронутые файлы до того, как фиксировать объём.
2. Если задача задевает UI/UX, собери handoff-заметку: запрос пользователя,
   файлы и маршруты в объёме, дизайн-решения, задачи на реализацию, ожидаемая
   валидация.
3. Заметки живут локально в `.agents/collab/`.
4. Не редизайнь смежные поверхности заодно.

## Инструмент

```bash
node .agents/skills/tatarverse-collab/scripts/handoff.mjs \
  --title "Короткое название задачи" \
  --request "Исходный запрос пользователя" \
  --scope "src/components/Example.astro" \
  --claude "UI/UX-направление" \
  --codex "Задачи на реализацию" \
  --validation "bunx astro check или точечная проверка в браузере"
```

Скрипт пишет markdown-заметку в `.agents/collab/` и печатает путь.

## Вывод

Кто что берёт, что уже изменено, где лежит handoff-заметка, какая валидация
была проведена.
