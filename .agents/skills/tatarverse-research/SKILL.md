# tatarverse-research

Скилл запускает исследование каталога центров: поиск новых организаций и
доведение существующих карточек до рабочего состояния.

**Содержание работы — в `docs/promt_search.md`.** Там контракт данных,
языки, каналы, правила проверки. Этот скилл — пусковой механизм: он
выясняет объём, спрашивает число агентов и собирает конвейер.

---

## Шаг 0. Спросить пользователя. Обязательно

**Никогда не выбирай число агентов сам.** Многоагентный запуск стоит денег и
времени, поэтому решение всегда за владельцем.

Сначала прогони аудит, чтобы вопрос был предметным:

```bash
node .agents/skills/tatarverse-research/scripts/audit.mjs
```

Затем задай **один** вопрос через `AskUserQuestion` с двумя полями:

**Поле 1. Режим**

- `Обновление (режим А)` — чинить существующие карточки. По умолчанию:
  без ссылок 288 из 421.
- `Поиск новых (режим Б)` — искать организации, которых в каталоге нет.
- `Оба` — сперва А, потом Б.

**Поле 2. Сколько агентов**

Предложи варианты и покажи потолок среды:

- `1 — только я, последовательно` — дешевле всего, ничего не запускается
  в фоне.
- `3 — осторожно` — рекомендуемый старт, видно, держит ли веб полосу.
- `6 — максимум среды` — потолок параллелизма, см. ниже.
- `Другое` — пользователь введёт своё.

В тексте вопроса укажи фактический потолок:

```bash
node -e "console.log('потолок: min(16, CPU-2) =', Math.min(16, require('os').cpus().length - 2))"
```

Не начинай работу, пока не получен ответ на оба поля.

## Потолок и три места, где параллелизм ломается

**Одновременно работает `min(16, CPU − 2)` агентов.** На восьмиядерной машине
это 6. Запросишь двадцать — шестеро работают, остальные ждут. Ориентир на
сессию: до 15 агентов на один проход.

Настоящие ограничения не в ядрах:

**1. Веб — общее горло.** Все агенты ходят через один `WebSearch` и
`WebFetch`. Шесть агентов не дают шестикратной выдачи и могут упереться в
лимит. Поэтому рекомендованный старт — 3, с подъёмом до 6, если полоса
держит.

**2. Номера `tbk-N` — гонка.** Два агента, создающие карточки одновременно,
оба увидят «последний занятый 425» и оба запишут `tbk-426`. Один файл затрёт
другой.

| Режим | Параллелится | Почему |
| --- | --- | --- |
| А — обновление | безопасно | каждый агент правит свой набор существующих файлов |
| Б — поиск | только до записи | этап записи строго последовательный |

**3. Дедупликация требует общего обзора.** Трек «Турция» и трек «татарский
язык» найдут одну организацию под двумя названиями. Сверять можно только
после того, как все закончили.

`bunx astro check` и `bun run build` — общерепозиторные, их гоняет один агент
в конце партии.

## Конвейер режима А (обновление)

Работа делится по странам, файлы не пересекаются, гонок нет.

```
N агентов, по стране на агента       крупные страны - по регионам
        ↓  барьер
astro check + build                  1 агент
        ↓
следующая партия
```

Порядок стран берётся из аудита по колонке «без ссылок». Сейчас 206 заглушек
из 288 приходятся на пять стран: Россия (141), Казахстан (30), Кыргызстан
(13), Украина (12), Узбекистан (10). Остальные 82 размазаны по 36 странам —
их удобно раздавать по одной на агента.

Партия — 10-20 карточек на агента.

Сузить аудит до страны:

```bash
node .agents/skills/tatarverse-research/scripts/audit.mjs --country Казахстан
```

## Конвейер режима Б (поиск)

```
preflight, доктор каналов            1 агент
        ↓
треки 1-3, по языковым кластерам     до N параллельно
        ↓  барьер
обход графа по свежим находкам       2-3 агента
        ↓  барьер
дедупликация                         1 агент, нужен общий обзор
        ↓
проверка кандидатов                  до N параллельно, только чтение
        ↓  барьер
запись карточек                      1 агент, строго последовательно
        ↓
astro check + build                  1 агент
```

**Трек 4 не идёт вместе с треками 1-3.** Он обходит граф связей *найденных*
организаций. Запущенный одновременно, он обойдёт только то, что уже в
каталоге, и потеряет главное — свежие находки. А это самый результативный
трек: крымскотатарский центр «Авдет» в Ташкенте пришёл именно через него.

Языки на карточку выбираются по формуле из `docs/promt_search.md`, раздел 5:
язык сообщества, русский, английский, язык страны, турецкий для тюркских.
Четыре-семь языков, не сорок.

## Что агент получает на входе

Каждому субагенту передавай:

1. Ссылку на `docs/promt_search.md` — весь контракт данных и правила.
2. Его участок: страна, список `tbk-N` или языковой кластер.
3. Результат preflight — какие каналы живы.
4. Явный запрет: **не создавать новые карточки**, если он не агент записи.
   Кандидатов возвращать структурированным списком.

Возврат от агента — данные, а не пересказ: найденные ссылки, контакты,
источники, уверенность, признаки дублей.

## Жёсткие запреты

Полный контракт в `docs/promt_search.md`, но это нарушают чаще всего:

- **`location.flag` в MDX** — флаг выводится из страны на рендере.
- **`pubDate` задним числом** существующей карточке — она выпрыгнет на первое
  место каталога, в RSS и в подвал, притворившись новинкой.
- **Личные мобильные и домашние адреса** — только публичные контакты
  организации.
- **Массовое удаление секции «Прочее»** — она есть у 274 карточек, но 164 из
  них содержат ОГРН и ИНН. Удалять можно только дословные дубли тела.
- **Страна вне `macroRegions.ts`** — роняет сборку. Сперва реестр, потом
  карточка.
- **Поле вне схемы** — она `.strict()`, сборка упадёт.
- **Русская карточка без английской.** Новый центр создаётся сразу в двух
  файлах: `src/data/centers_formatted/<id>.mdx` и
  `src/data/centers_i18n/en/<id>.mdx`. Без второго центр не «ждёт перевода», а
  пропадает из `/en/centers` и английского поиска целиком: английская
  коллекция отдаётся вместо русской, а не поверх неё. Конвенции перевода — в
  скилле `tatarverse-astro-content`, раздел «Новая карточка центра»; `type` и
  `category` в английском файле остаются русскими.

## Отчёт

По форме из `docs/promt_search.md`, раздел 11. Обязательно укажи:

- сколько агентов реально работало и сколько фаз шло последовательно;
- таблицу каналов из preflight — что было недоступно;
- что искали и **не нашли** — это дописывается в
  `docs/CENTERS-GAPS-CHECKLIST.md`, чтобы следующий проход не повторял.
