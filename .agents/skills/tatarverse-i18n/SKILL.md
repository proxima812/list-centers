# tatarverse i18n

Один скилл на всю работу со словарями: и точечное добавление ключей, и
аудит полноты. Раньше это были два скилла (`i18n-keys` и
`i18n-audit-tester`), они разошлись.

## Как устроено

- Словари: `src/i18n/locales/ru.ts`, `src/i18n/locales/en.ts`.
- Реестр локалей, `localeLabels`, `dictionaries`, `ogLocales`,
  `unlocalizedPathnames` - `src/i18n/index.ts`. Типы UI - `src/i18n/ui.ts`.
- `ru` - дефолтная локаль, отдается без префикса; `en` живет под `/en/`
  и в `src/pages/[locale]/`.
- Часть маршрутов намеренно одна на обе локали (`unlocalizedPathnames`:
  `posts`, `sabantye`, `saved`) - для них строки русские, это не баг.

## Новый ключ

1. Добавь одинаковый ключ во **все** locale-файлы сразу.
2. В компоненте: `const t = useTranslations(locale)` и `t("your.key")`.
3. Интерполяция - через `{count}` и `t("key", { count })`.
4. Имя ключа - по зоне: `nav.*`, `menu.*`, `home.*`, `list.*`, `detail.*`,
   `card.*`, `footer.*`, `feedback.*`, `copy.*`.
5. Хардкод UI-строк не оставляй.

## Новый язык

1. Создай `src/i18n/locales/<lang>.ts` на основе `ru.ts`.
2. Добавь язык в `locales` в `src/i18n/index.ts` и в `src/i18n/ui.ts`.
3. Заведи `localeLabels`, `dictionaries`, `ogLocales`.
4. Проверь роутинг `/<lang>/...` и переключатель языка.

## Аудит

```bash
node .agents/skills/tatarverse-i18n/scripts/audit-i18n.mjs
```

Скрипт читает `src/i18n/locales/*.ts` и вызовы `t("...")` по `src/**` и
показывает три блока:

- `missingInLocales` - ключ есть не во всех словарях. Всегда чинить.
- `missingUsedKeys` - ключ используется в коде, но его нет в словарях.
  Всегда чинить.
- `unusedLocaleKeys` - **не всегда ошибка**: SEO-строки, будущие страницы и
  динамически собранные ключи валидны. Прежде чем удалять, найди причину.

После правок повтори аудит: missing-блоки должны быть пустыми.

## Правила

- Не рефакторь структуру i18n ради аудита.
- Не заливай машинный перевод пачкой: если контекст спорный, дай короткий
  вариант и явно скажи о риске.
- Существующие переводы не переписывай без причины.
